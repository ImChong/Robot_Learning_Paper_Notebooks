# EmbodyHOI: Embodiment-Aware Generation of Hand-Object Interactions for Humanoid Dexterous Manipulation
**在冻结的文本到手-物交互（HOI）流匹配生成器的每一步采样里，对目标人形跑一次可微逆运动学（手臂关节 + 站位一起解），把 IK 残差的梯度当分类器引导加到手部 token 的速度场上；生成的双手轨迹一边生成一边变得「这台机器人够得着」，再重定向给 PPO 跟踪策略，G1 上 50 个随机 ARCTIC 任务成功率 68% → 79%，H1-2 四任务 62% → 76%，换机器人只换 IK 模块、不用重训生成器**

## 🎯 一句话总结

文本到 HOI 生成器能给出丰富、按语言指定的双手演示，但它在人手（MANO）空间里生成，手腕放在哪完全不管机器人够不够得着；等到事后重定向才发现手臂到不了，这时手指和物体轨迹早已定死。EmbodyHOI 的看法是**可达性应当在交互生成的过程中约束它**：在冻结生成器的每个流匹配 ODE 步里解码出当前手腕轨迹，对目标人形做「手臂关节 + 站位平移」联合 LM 求解，再通过隐式微分把 IK 能量的梯度送回手部潜 token（物体 token 的梯度置零）；后面揭开的手指和物体 token 会围着修正后的手腕重新长出来。重定向后的 G1 手腕误差从 8.9 cm / 20° 降到 0.6 cm / 4°，生成质量不降（FID 0.667 → 0.545）。论文还专门说明：事后修手腕、同算力 best-of-32 挑样本都能把 IK 能量压得更低，却训出更差的策略——IK 能量只能在交互内容不变时当诊断量，不能单独去最小化。

## ❓ 要解决什么问题？

1. **HOI 生成器不知道谁来执行**：手腕轨迹只在 MANO 空间里合理，换成手臂只有 45 cm 的 G1，很多手腕目标根本够不着或贴近奇异位形，重定向后跟踪策略继承的就是到不了的目标；
2. **两头的现有修法都不理想**：在机器人空间里训生成器（DreamControl-v2）一台机器人一个生成器、无法复用；事后修补人类动作（DemoDiffusion、Chen 等）只能做小幅改动，修不好够不着的手腕，而且改手腕时手指和物体已经定了；
3. **整台人形比漂浮手多一个问题——站在哪**：站位决定整个交互过程中两只手臂是否都够得着；固定站位的 IK 分不清「站错位置的可行交互」和「本身不可行的交互」。

## 🔧 方法

### 1. 生成器：冻结的 MAD-HOI

输入文本和关节物体网格，输出物体轨迹（位置、朝向、关节角）和左右手的 MANO 轨迹（手腕平移、手腕朝向、15 个手指关节，旋转用 6D 表示）。物体、左手、右手是**分开的潜 token**；掩码自回归 Transformer 每一轮揭开一批 token，揭开的 token 由流匹配头积分 ODE $\dot{\mathbf{x}} = \mathbf{v}_\theta(\mathbf{x}, t, \mathbf{z})$ 生成。本文要用到它的两个性质：采样中途任何时候都能**可微地解码出手腕**；手和物体 token 分开，梯度可以只给手、不给物体。

### 2. IK 引导：把可达性梯度加到速度场上

照分类器引导的形式，在流匹配速度场上减去能量梯度：

$$\dot{\mathbf{x}} = \mathbf{v}_\theta(\mathbf{x}, t, \mathbf{z}) - w\,\nabla _ {\mathbf{x}} E(\mathbf{x})$$

- **能量怎么算**：把当前潜变量连同已揭开的 token 解码出双手手腕轨迹，当作任务空间目标，在目标人形上逐帧解 IK。优化变量是手臂关节 $\mathbf{q}^t$ 加**站位平移** $\mathbf{b}^t \in \mathbb{R}^3$（朝向固定）；每只手的残差是目标手腕位姿与「站位 × 正运动学」之间的 SE(3) 对数（位置、朝向分开加权）。
- **两组正则**：站位组——离当前首选站位 $\mathbf{b}_0$ 别太远、与物体保持一定水平距离；手臂条件组——靠近休息姿态、关节限位、和上一帧解别差太多（顺便热启动）、解完后在两只手腕任务的零空间里对 $1/\sigma _ {\min}(\mathbf{J}_h)$ 走几步梯度，提高可操作度又不挪手腕。
- 残差叠起来用 LM 解 10 次迭代，IK 能量 $E$ 是残差平方在 $T$ 帧上的平均。
- **梯度怎么回来**：在 JAX 里对 LM 解做隐式微分（不展开迭代），经 JAX–PyTorch 桥穿过解码器到潜变量；更新前把物体 token 的梯度置零，引导只直接作用于手部 token，物体和手指在后续揭开的 token 里跟着修正后的手腕重新形成。
- **站位跟着动作走**：执行时站位是固定的，所以每轮揭开之后把逐帧站位取平均作为下一轮的先验 $\mathbf{b}_0$；它从每台机器人一个手设的初值开始，每轮的中位数变化从开头约 1.3 cm 收敛到最后 0.06 cm。
- **超参数**：18 轮揭开，每轮 RK4 积分 20 步，每一步都加引导，$w = 0.5$，从第一轮就开始；所有权重对两台机器人、两个生成器、所有任务只设一次。代价是采样慢 32 倍（A100 上一条参考 5 s → 160 s），但每条参考只付一次，摊到约 4 h 的策略训练上。

### 3. 重定向与策略学习

- **目标机器人**：Unitree G1 + 两只 XHand；上身 15 个可控自由度（躯干 + 双臂），下身固定，每只手 12 个自由度。
- **重定向**：PyRoki 从优化后的站位把引导后的手腕解成手臂关节轨迹；dex-retargeting 把 MANO 手指映射到 XHand；接触重定向照 DexMachina 得到参考接触。生成的物体轨迹提供观测、奖励和终止用的参考物体位姿与关节角。
- **PPO 跟踪策略**（Genesis 仿真，MLP，单张 RTX 4090 训约 4 h）：观测含关节位置 / 速度 / 动作的短历史、回合相位、未来 $\Delta \in \{1, 2, 4, 8, 16\}$ 步的参考关节偏差、物体部件位姿与关节角及其未来跟踪误差。动作 39 维：上身 15 维是**在上一次关节目标上的增量**（大幅手臂动作更平滑），手指 24 维是**绝对目标**（关节范围小）。不对物体施加任何虚拟控制，所以不需要 DexMachina 的虚拟物体课程。
- **手臂与手分开奖励、分开终止**：空间中粗粒度的够取与富接触的手指控制误差尺度不同，一项覆盖 39 维的模仿奖励会偏向误差大的那一边。于是拆成上身 15 维 $r _ {\mathrm{imi,upper}}$ 和手指 24 维 $r _ {\mathrm{imi,dex}}$，各有权重和温度；终止也一样：手臂按**最大**关节误差终止（手臂一大错整段就废了），手指按**平均**误差终止（个别手指偏一点不致命）。另有物体跟踪、接触匹配和常规的动作 / 速度 / 加速度 / 力矩惩罚。

## 🚶 具体实例

**① 引导的算力账**：18 轮揭开 × 每轮 20 个 RK4 步 = 360 个 ODE 步，每一步都要解码手腕、解一次 LM（10 次迭代）再反传梯度，所以一条参考从 5 s 涨到 160 s（32 倍）。这也是表 I 里 best-of-$N$ 用 $N = 32$ 做「同算力」对照的原因。

**② 为什么挑样本比修样本更容易压低能量**：同一个提示词下，不同样本的 IK 能量标准差是 0.36，而引导对一个样本的中位数改动只有 0.04，相差约 9 倍——多抽几条总能碰到能量更低的。但挑出来的样本手腕离种子对应的那条平均 13 cm，等于换了一个交互；引导只把手腕挪 0.3 cm、穿透和接触几乎不变。结果训出的策略：best-of-32 74.0%，引导 79.7%，差 5.7 ± 0.7 个点。

**③ 事后修手腕为什么最差**：在生成完的样本上直接用 Adam 对同一能量优化 100 步，能量最低（0.35），但手腕被挪了 32.6 cm，手指和物体却没跟着变，穿透从 0.52 涨到 0.59，成功率掉到 32.8%（比什么都不做的 68.1% 还低一半多）。

**④ 表 III 的阶梯**（G1 四任务套件）：ARCTIC 真值、固定站位 + DexMachina 式 RL 66.8% → 换成未引导的生成样本 68.2%（+1.4，生成只带来多样性、不带来可达性）→ 事后优化站位 + 本文 RL 配方 73.6%（+5.4）→ 加 IK 引导 79.3%（+5.7）。拿掉站位组掉到 75.3%（−4.0），拿掉手臂条件组掉到 76.4%（−2.9）；反过来看单独站位组比 C 行多 2.8、单独手臂组多 1.7，合起来 4.5 < 5.7，两组一起比单独加起来更有用。

**⑤ 同一个目标，两台机器人站得不一样**：H1-2 手臂 68.5 cm，是 G1 45 cm 的约 1.52 倍。从同一个初始站位出发，引导把 H1-2 往**后**推（手臂太长会伸过头），把 G1 往**前**、往高处挪（够不着）；目标函数里没有任何一项专门写这两种行为，都是同一个残差算出来的。

## 📊 实验与结果

协议：G1 + XHand，固定四任务套件（开盒子、提华夫饼机、开合搅拌机、提起并放下微波炉）和 50 个不预选的随机 ARCTIC 任务；5 个训练种子、每任务 10 轮 × 并行环境，物体初始化随机。

**表 I（51 个种子对齐提示词，四任务成功率）**

| 方法 | 采样代价 | IK 能量 ↓ | 手腕位移 (cm) | 穿透 ↓ | SR % ↑ |
|---|---|---|---|---|---|
| 未引导、固定站位 | $t_1$ | 2.30 | – | 0.52 | 68.1 ± 0.3 |
| + 站位优化 | $t_1$ | 1.89 | 0 | 0.52 | 73.3 ± 0.5 |
| **+ IK 引导（本文）** | $32\,t_1$ | 1.81 | 0.3 | 0.53 | **79.7 ± 0.4** |
| 事后 IK 修正 | $t_1$ + IK | 0.35 | 32.6 | 0.59 | 32.8 ± 0.3 |
| best-of-8（按 $E$） | $8\,t_1$ | 1.36 | 13.2 | 0.52 | 73.1 ± 0.6 |
| best-of-32（按 $E$） | $32\,t_1$ | 1.21 | 13.7 | 0.51 | 74.0 ± 0.6 |

**表 II（400 个 ARCTIC 测试提示词）**：引导后 FID 0.667 → 0.545、Top-3 0.852 → 0.872、多样性 19.77 → 19.85、接触率 83.5% → 83.1%、穿透 12.2% → 11.5%，KID 0.001 → 0.003；重定向后 G1 手腕误差 **8.9 cm / 20.2° → 0.6 cm / 4.0°**。

**其他结论**

- **条件数**：只优化站位就把接近奇异的样本（$\sigma _ {\min} < 0.03$）从 2.6% 降到 0.2%；之后 $\sigma _ {\min} \approx 0.086$、条件数约 26 已经是这条链的上限，引导不再改变它，而是去掉重定向后残留的误差（83% 的提示词能量下降）。
- **随机任务**：50 个随机任务 68% → 79%；其中未引导参考条件最差的 10 个 57.9% → 82.1%——收益集中在可达性差的少数任务上。
- **奖励设计**：只用模仿 44.5%、只用物体跟踪 58.2%、39 维共用一项模仿 74.1%、手臂 / 手指分开 79.3%。
- **跨本体**：H1-2 上 46 / 50 个提示词能量下降（中位数 2.06 → 1.95），四任务成功率 62.3% → 75.7%（+13.4，与 G1 的 +11.6 相当）。
- **跨生成器**：同一目标函数不改一行用在 Text2HOI（DDPM，在预测的 $x_0$ 上走梯度）上，G1 48 / 50、H1-2 50 / 50 个提示词能量下降，但幅度只有约 1%（它自带的接触细化器会再改手）。
- **对照上限**：DexMachina 原版（漂浮手腕、没有手臂）在同样任务上 86.1%，论文把它和 79.3% 的差距解释为手臂可达性约束本身的代价。

## 💡 核心贡献

1. **无需训练的 IK 引导**：对冻结 HOI 生成器的每个 ODE 步做目标人形上的可微 IK，梯度只推手部 token；一套权重服务 G1、H1-2 和两种生成器；
2. **站位进入引导**：手臂关节与站位平移联合求解，并在每一轮揭开后更新站位先验——在循环里解站位比生成后解一次多出 2.8 个点；
3. **「能量更低 ≠ 参考更好」的反例**：事后修正和同算力挑样本都比引导的 IK 能量低，却训出更差的策略；
4. **手臂 / 手指解耦的奖励与终止**：在两台人形上把成功率提高 11–13 个点。

## 🤖 对人形机器人的启示

- 用人类数据训练的生成器做机器人参考时，与其每台机器人重训一个生成器，不如把机器人的运动学约束做成**推理时的能量**——换机器人只换这个模块；
- 约束要在**还能改其他部分的时候**加：手腕改了，手指和物体能跟着改，交互才不散；事后只挪手腕会把手指和物体的配合拆散；
- 可行性指标（IK 能量、条件数）只适合在交互内容固定时比较，直接把它当优化目标去挑或去修，会以牺牲交互本身为代价；
- 整台人形的灵巧操作里，「站在哪」往往比手臂姿态的细调更值钱，而且几乎不花采样成本。

## ⚠️ 局限与可改进点

- **只管运动学**：可达不代表动力学、接触上可行，这部分仍交给 RL 去吸收；
- **采样慢 32 倍**：论文建议只在部分揭开轮次里加引导；或者用引导后的样本微调生成器，把引导蒸馏进先验（代价是又变成一台机器人一个生成器）；
- **下身固定**：只优化站在哪、不管怎么走过去，和行走控制器的结合留作后续；
- **全部在仿真**、只用 ARCTIC 的关节物体，还没有真机实验；代码与生成的参考尚未放出。

## 🎤 面试参考

1. **为什么只给手部 token 加梯度、物体 token 置零？** 物体轨迹是任务本身（要把盒子打开），不该为了机器人够得着去改；而手指、物体 token 在后续轮次里会以引导后的手 token 为条件重新生成，交互自然围着新手腕形成。
2. **为什么要把站位一起解？** 固定站位时可达性只取决于轨迹，「站错地方的可行交互」和「本身不可行的交互」都会被判成高能量；联合求解站位，梯度才只推真正够不着的部分。
3. **IK 能量那么低的事后修正为什么失败？** 它在手指和物体已定的情况下挪手腕 30 多 cm，手和物体的相对关系被破坏、穿透上升；能量只衡量手腕可达性，看不到交互是否还成立。
4. **为什么用隐式微分而不是展开 LM 迭代？** 在解的最优性条件上求导，梯度与迭代次数无关、显存和计算都省，也不受截断迭代带来的偏差影响。
5. **上身动作为什么用增量、手指为什么用绝对目标？** 手臂运动幅度大，增量让轨迹平滑；手指关节范围小，直接给绝对目标更好学、也不会累积漂移。
